# IBS-0003 — Evidence and result format

Status: draft 0.1, proposed. JSON schema and canonical serialization pending.

Bundle includes manifest, environment, methodology, corpus lock, implementation lock, observations (JSONL), validation, statistics, scores and checksums. Every record links to immutable run/configuration/input IDs. Record schema and profile versions; distinguish native measurements from imports.

Observation fields: run_id, observation_id, worker_id, block_id, sequence, input_id, config_id, operation, status, original_bytes, output_bytes, elapsed_ns, invocation_count, validation_ref, probe readings and provenance. Integer byte and time values require exact serialization; decide interoperable integer bounds before schema finalization. Batch records identify total work and total elapsed time. Missing fields use explicit status/reason; errors cannot masquerade as zeros.

Validation records identify artifact, expected digest/length, actual digest/length, method and cadence. Statistics identify observation IDs, estimators, weighting, exclusions and uncertainty. Scores identify metric versions, baseline/profile/candidate set where applicable and eligibility. Imports retain source URL/version/digest and unavailable provenance; do not synthesize raw trials.

Verification levels: schema validity, checksum integrity, derived-result recalculation, independent reproduction. These are distinct claims. Checksums alone do not prove authenticity; signatures and trust model remain open.

Acceptance: round-trip schema fixtures, corrupted checksums, unknown schema versions, missing required metrics, imported aggregate-only results, and deterministic score recalculation.
