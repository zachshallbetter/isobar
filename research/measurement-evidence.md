# Measurement and conformance evidence

## Reproduced upstream behavior

The fixture reads source blobs from pinned Git commits. For the C and C++ cases it compiles the selected upstream lines without edits, with fixture-supplied inputs and hooks. The Python cases call the pinned functions. These executions test specific paths and do not measure upstream codec performance. The run used Apple clang 21.0.0 and CPython 3.13.18 on ARM64 macOS.

| Finding | Executed path and controls | Observed result |
| --- | --- | --- |
| L02, mixed timing units | lzbench timed two calls at 12,000 and 30,000 synthetic ns, with 2,000 ns between calls | Sample vector contained both calls and the batch estimate: [12,000, 22,000, 30,000] ns. Mixed median was 22,000 ns; invocation median was 21,000 ns. The batch observation, 44,000 ns for two calls, includes inter-call overhead. |
| L03, last-invocation validation | lzbench ran two equal-length decodes, with a byte difference injected into the first or last decode | The clean and bad-first batches passed the batch-end check. The bad-last batch set the decode error flag and exit state 11. This is a check-cadence limitation of the exercised loop, not evidence of intermittent errors in a real codec. |
| T02, comparator contract | TurboBench comparator with equal ranking keys and IDs, then different IDs as a control | Self-compare returned −1. Both orders of distinct rows sharing the same ID returned −1. Different IDs broke the tie by ID. The fixture calls the comparator directly and makes no claim about how a particular libc sorts invalid comparisons. |
| T04, disabled metric in tie assignment | TurboBench ranked equal-size records with encode times 2 and 1, first with size alone, then with encode time enabled | Ranks by input row were [1, 2] with size alone and [2, 1] with encode time enabled. Equalizing encode time yielded [1, 1]. |
| W01, excluded finalization | Weissman baseline wrapped a real gzip stream and used deterministic write and close increments of 2 and 3 clock ticks | The baseline reported 2 of 5 ticks. Close completed before the file length was read. The target path brackets subprocess completion. The synthetic increments establish boundaries, not the size of the effect on real workloads. |
| W03, insufficient qualification | Weissman ran a disposable child process that produced one non-gzip byte from a seven-byte input | The target returned a ratio of 7 without decoding the artifact. This shows that size and process success alone do not establish losslessness. |
| W04, historical log behavior | Weissman used controlled durations and unit ratios | Candidate time 1 triggered `ZeroDivisionError`. Reference 0.5 and candidate 0.25 scored 0.5 despite faster encoding. |

## Static execution paths and upstream test coverage

- **lzbench.** The timer chooses QPC on Windows, `mach_absolute_time` on macOS and `CLOCK_MONOTONIC` on its other branch. The runner creates work contexts before timing and calls chunk adapters within the interval. Its regular Zstandard adapter reuses contexts, sets level and content-size flags, may set worker count/window parameters, and calls `ZSTD_compress2`. The reviewed top-level workflow publishes pages. Tests inside bundled codecs are separate from verification of runner cadence. - **TurboBench.** The timed encode loop calls `codcomp` per block. The ordinary Zstandard path creates a context, applies parameters, finishes the stream and frees the context inside the adapter call. TurboBench can time cycles or elapsed time. The repetition macros select a minimum batch time and calibrate repetition counts. The reviewed Linux CI exercises a micro-codec smoke run. Its coverage should not be taken as evidence of rank comparator invariants. ## Measured gzip boundary pilot

Five independent processes ran four blocks each with three inputs per block, for 60 exact round trips. After one warm-up per input per process, the workload order was shuffled within each block. Each invocation used level 6, an existing in-memory sink and a fresh gzip stream. Four monotonic timestamps bracketed initialization, write and close. The same invocation provided both the write-only interval and the whole interval. The decoder ran outside both intervals. The stored observations retain input/format sizes, all segment durations, worker and block identity, and actual order.

| Input | Input bytes | Artifact bytes | Median omitted share |
| --- | ---: | ---: | ---: |
| Tiny text | 31 | 51 | 96.0% |
| Repeated text | 262,144 | 428 | 2.7% |
| SHAKE256-generated bytes | 262,144 | 262,242 | 1.0% |

Omitted share is `(whole_ns − write_ns) / whole_ns`, summarized as the median of the 20 paired observations per input. These local values describe an instrumented CPython 3.13.18/zlib 1.2.12 in-memory path on ARM64 macOS. Timer overhead was not subtracted, and the tiny fixture is especially sensitive to it. The experiment does not reproduce Weissman's filesystem/subprocess workload or estimate speedups. [Raw JSONL](experiments/gzip-boundaries.jsonl) · [pilot driver](experiments/gzip-boundaries.py) · [CPython finalization](https://github.com/python/cpython/blob/0d4bd512fc429e3d4eacdd113c975e161f21644d/Lib/gzip.py#L368-L388).

## Literature and standards implications

- Kalibera and Jones distinguish builds, process executions and within-process iterations as possible sources of variation (§§2–5). For a fixed build, report this conditioning and use independent workers as the outer repetition unit. Within-worker batches can estimate serial throughput, but treating all invocations as independent would change the claimed uncertainty. Pilot variance and cost before selecting repetitions. A paired, workload-specific effect can resample whole independent blocks when those blocks are actually independent; blocks nested in one worker must remain nested under resampling. No production interval or stopping rule has been selected. [Rigorous Benchmarking in Reasonable Time](https://kar.kent.ac.uk/33611/45/p63-kaliber.pdf).
- Mytkowicz et al. used controlled link-order and environment-size interventions and showed setup-dependent conclusions (§§3–5, 7). Record candidate order, build and environment, and balance the order of two candidates within blocks. Order balancing addresses one identified nuisance factor. When the target of inference includes build variation, repeat builds or randomize the relevant setup factors explicitly. [Producing Wrong Data Without Doing Anything Obviously Wrong!](https://web.eecs.umich.edu/~weimerw/2022-481F/readings/producing-wrong-data.pdf).
- A gzip artifact may contain multiple members. The fixture decodes a two-member artifact to `AB` using CPython's full gzip API. The single-member zlib control produces `A` and returns 21 unused bytes. CRC and length checks in these vectors describe the chosen validation profile and tested CPython behavior. Whole-artifact acceptance must distinguish end of member from end of artifact. [RFC 1952 §§2.2–2.3](https://datatracker.ietf.org/doc/html/rfc1952#section-2.2) · [CPython member loop](https://github.com/python/cpython/blob/0d4bd512fc429e3d4eacdd113c975e161f21644d/Lib/gzip.py#L619-L642).
- Zstandard defines concatenated frames and skippable frames. The built v1.5.7 CLI decoded both ordinary concatenation and a skippable frame between data frames to `AB`. Truncating the second frame caused a nonzero exit after stdout had already emitted the first frame’s byte, `A`. Its path checks frame markers in an outer loop and calls the streaming decoder until each frame ends. The upstream CLI tests exercise concatenation with and without checksums. RFC 9659 limits the window for HTTP content encoding; apply that scope separately from generic file-format conformance and from Isobar resource budgets. [RFC 8878 §3.1](https://datatracker.ietf.org/doc/html/rfc8878#section-3.1) · [RFC 9659](https://datatracker.ietf.org/doc/html/rfc9659) · [CLI dispatch](https://github.com/facebook/zstd/blob/f8745da6ff1ad1e7bab384bd1f9d742439278e99/programs/fileio.c#L2722-L2764) · [stream loop](https://github.com/facebook/zstd/blob/f8745da6ff1ad1e7bab384bd1f9d742439278e99/programs/fileio.c#L2451-L2497) · [upstream tests](https://github.com/facebook/zstd/blob/f8745da6ff1ad1e7bab384bd1f9d742439278e99/tests/playTests.sh#L922-L940).
- For interoperable evidence counters, the experimental schemas use the nonnegative subset of RFC 8259's exact binary64 integer range. JSON Schema evaluates parsed values. Reject duplicate keys before validation, and check numeric wire values before lossy conversion so that `9007199254740991.1` cannot become a permitted integer. Cross-record references and qualification also require a semantic pass. Canonical serialization and signing remain separate design questions. [RFC 8259 §§4, 6](https://datatracker.ietf.org/doc/html/rfc8259#section-6) · [JSON Schema Draft 2020-12](https://json-schema.org/draft/2020-12/json-schema-validation) · [RFC 8785 §3](https://datatracker.ietf.org/doc/html/rfc8785#section-3).

## Open questions

Upstream fixtures cover selected source paths. Full runner behavior on real corpora, multithreaded validation, Windows/Linux probe semantics, uncertainty calibration, imported provenance, production worker containment and artifact signing remain open. The formats exercised here are gzip and Zstandard. Corpus redistribution rights and dictionary training/evaluation policy still need separate evidence.

## Whole-artifact adapter checks

All 11 format vectors ran through both roles on ARM64 macOS. The gzip candidate used CPython 3.13.18 with zlib 1.2.12. The gzip reference used libdeflate 1.25 at `c8c56a20f8f621e6a966b716b31f1dedab6a41e3`. The Zstandard streaming candidate and one-shot reference used the same libzstd 1.5.7 build at `f8745da6ff1ad1e7bab384bd1f9d742439278e99`. Both shared libraries were compiled with Apple clang 21.0.0. The checker emits SHA-256 digests of the native libraries and the CPython zlib binding for each run. The binding digest identifies the Python extension, and the linked zlib is identified by runtime version.

The candidate gzip path produced both payload bytes before finding the incomplete second trailer. Both streaming candidates consumed the entire truncated input and still rejected it. [libdeflate API](https://github.com/ebiggers/libdeflate/blob/c8c56a20f8f621e6a966b716b31f1dedab6a41e3/libdeflate.h#L288-L314) · [gzip trailer checks](https://github.com/ebiggers/libdeflate/blob/c8c56a20f8f621e6a966b716b31f1dedab6a41e3/lib/gzip_decompress.c#L102-L132) · [Zstandard frame extent](https://github.com/facebook/zstd/blob/f8745da6ff1ad1e7bab384bd1f9d742439278e99/lib/zstd.h#L216-L227) · [Zstandard streaming semantics](https://github.com/facebook/zstd/blob/f8745da6ff1ad1e7bab384bd1f9d742439278e99/lib/zstd.h#L926-L948).
